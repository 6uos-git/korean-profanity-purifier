# 문맥 보존형 비속어 순화기 (project/)

교재 저장소(deep-learning-from-scratch-2) 안에 **원본 수정 없이** 신규 파일로 구현.
발표자료 `미니프로젝트1_발표자료_비속어순화기.pdf` 20쪽 구성(8개) + 실험·실데이터 파일 3개.

| 파일 | 내용 | 구분 |
|---|---|---|
| jamo.py | 정규화, 자모 분해·결합 (종성은 `_ㄴ`처럼 별도 토큰 → 음절 경계 보존) | 교과 외 |
| make_pairs.py | 역방향 생성 (순화어 사전 거꾸로 + 초성화·숫자/기호 삽입·유사 자모) | 교과 외 |
| loader.py | 자모/음절 어휘, 패딩·마스크, ch05 형식 LM 말뭉치, 데이터셋 읽기 함수 | Ch05 형식 + 교과 외 |
| layers_ext.py | `TimeBiRNN`(ch05 TimeRNN×2, 길이 안에서만 역순), `MaskedTimeSigmoidWithLoss` | 교과 외 |
| models.py | `RnnDetector`, `SentenceLM`(ch05 SimpleRnnlm 상속), `SentenceClassifier`(E7·심판용) | Ch04~05 |
| purifier.py | 탐지 → 분기 → 후보 치환 → LM 선택 → 재검증, 구간 히스테리시스, E1 사전 | 교과 외 + Ch05 |
| evaluate.py | 구간 F1, STA·SIM(문자 BLEU)·FL·J, 과교정률, 손으로 쓴 평가 문장 25개 | 교과 외 |
| train_demo.py | 예시 문장으로 학습, E1~E4 | Ch05 |
| experiments.py | E5 음절 vs 자모, E6 랜덤 vs word2vec(ch04 CBOW), E7 태거 vs Leave-one-out | 교과 외 + Ch04 |
| kcbert_fill.py | E8 KcBERT Mask-and-Fill (사전 차단·재검증·반복 제한) | 교과 외 |
| real_data.py | 실제 데이터셋 5종 연결, 실제 욕설 200문장 평가 | 교과 외 |

## 실행

```bash
cd project
python3 -m venv .venv && .venv/bin/pip install numpy matplotlib   # E8은 torch transformers 추가
.venv/bin/python train_demo.py    # E1~E4 (약 20초)
.venv/bin/python experiments.py   # E5~E7 (약 1분)
.venv/bin/python kcbert_fill.py   # E8 (처음엔 beomi/kcbert-base 약 440MB 내려받음)
.venv/bin/python real_data.py     # 실제 데이터 (약 3분)
```

실제 데이터는 `data/`에 각 저장소를 clone (라이선스상 재배포하지 않으므로 `.gitignore` 처리). KOLD는 Git LFS 필요.

```bash
mkdir -p data && cd data
git clone --depth 1 https://github.com/2runo/Curse-detection-data.git
git clone --depth 1 https://github.com/boychaboy/KOLD.git            # brew install git-lfs 먼저
git clone --depth 1 https://github.com/smilegate-ai/korean_unsmile_dataset.git
git clone --depth 1 https://github.com/kocohub/korean-hate-speech.git
git clone --depth 1 https://github.com/adlnlp/K-MHaS.git
```

## 결과 1 — 예시 문장 (동작 확인용)

| 손으로 쓴 25문장 | STA | SIM | FL | J | 정답 일치 | 과교정 |

- E8은 자연스럽지만 자유롭게 채움("저 ㅅㄲ" → "저 여자는"), 원래 표현 후보가 없어 오탐 문장도 바꿈("수업이 끝났다" → "수업이 아니라다"). 정답 일치·FL은 E4 후보 목록과 같은 어휘라 E4에 유리한 지표임에 주의. 속도 E4 2ms vs E8 35ms/문장

### 실제 데이터에서 확인한 것 (정직한 해석)

- **예시 데이터 성능은 실제로 이어지지 않음.** 생성 데이터 J 0.77~0.80 → 실제 0.27
- 1차 실행에서 양방향 탐지기가 주입 **위치**를 외움(명시적 재현율 0.50) → 주입 위치·형태를 무작위화하자 0.66~0.74. 실행마다 편차가 커서 여러 시드 평균이 필요
- 실제 데이터에서는 **단방향이 재현율, 양방향이 정밀도**에서 우세 — 예시 데이터와 다른 결과
- 순화 단계 약점: 문장 평균 퍼플렉서티는 후보 간 차이가 작아 문맥에 안 맞는 후보("사람들아")가 뽑힘, 구간이 어절 일부만 잡히면 조각 출력("노가다사람들아")
- 심판 분류기 정확도 0.68이라 STA는 참고값. 비속어 패턴 잔존율을 함께 볼 것

## 다음 과제

1. 후보 채점을 문장 평균이 아닌 **치환 구간 주변 국소 퍼플렉서티**로 변경 (가장 큰 오류 원인)
2. 구간을 어절 단위로 맞추고 조사 보존 (새끼들이 → 사람들이)
3. 실제 욕설 구간 라벨 소량(수백 문장) 직접 작성 → 주입 데이터와 섞어 학습, 여러 시드 평균
4. E5를 실제 데이터로 재실험 (변형 다양성이 큰 환경에서 자모 효과 검증)
